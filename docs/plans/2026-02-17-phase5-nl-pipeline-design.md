# Phase 5: Natural Language Reasoning Pipeline

## Overview

End-to-end NL-in, NL-out reasoning pipeline built around the frozen Phase 4 GNN+TAT+Ensemble+LLM core. Free-form natural language queries are parsed into graph structures, reasoned over by the trained topological model, and explained back in natural language.

**Approach:** Sequential pipeline (Approach A). Each component is independently testable. Frozen core means zero regression risk.

**Phased delivery:**
- Phase 5a: Few-shot prompting for parsing and generation. Heuristic task routing. Working prototype with no new training.
- Phase 5b: Synthetic training data + LoRA fine-tuning where few-shot falls short. Learned task router.

## Architecture

```
NL Query → [GraphParser] → GraphSpec (JSON)
         → [TaskRouter] → task_type + query/target
         → [CellComplexBuilder] → CellComplex (reuses nx_to_cell_complex)
         → [Frozen HierarchicalMultiHopModel] → class_idx
         → [AnswerGenerator] → NL explanation
```

### Module Summary

| Module | What it does | Phase 5a | Phase 5b |
|--------|-------------|----------|----------|
| GraphParser | Llama extracts entities/relations → JSON | Few-shot prompt | + LoRA adapter |
| TaskRouter | Picks task type + query/target nodes | Heuristic rules | + learned classifier |
| CellComplexBuilder | JSON → NX → CellComplex | Wrapper only | Same |
| Frozen model | GNN+TAT+Ensemble reasoning | Phase 4 checkpoint | Same |
| AnswerGenerator | Class idx + graph → NL explanation | Few-shot prompt | + LoRA adapter |

## Data Structures

```python
@dataclass
class GraphSpec:
    nodes: list[NodeSpec]       # name, type, attributes
    edges: list[EdgeSpec]       # source_name, target_name, relation
    query_node: str             # which node is being asked about
    target_node: str | None     # optional second node
    domain: str                 # inferred domain (technology, biology, etc.)

@dataclass
class NodeSpec:
    name: str
    type: str                   # "component", "event", "entity", etc.

@dataclass
class EdgeSpec:
    source: str
    target: str
    relation: str               # "causes", "prevents", "enables", "connects"

@dataclass
class TaskRoute:
    task_type: str              # one of 14 TASK_REGISTRY keys
    query_node_idx: int         # index in CellComplex
    target_node_idx: int        # index in CellComplex
    max_classes: int            # from get_max_classes(task_type)
    metadata: dict              # task_prompt, node_labels, etc.

@dataclass
class NLResult:
    answer: str                 # NL explanation
    class_idx: int              # raw model prediction
    task_type: str              # which task was routed to
    graph_spec: GraphSpec       # extracted graph
    confidence: float           # from model's softmax
```

## Module Designs

### GraphParser

Takes free-form NL and produces a GraphSpec via Llama structured output.

**Phase 5a — Few-shot prompting:**

Llama receives a system prompt with 3-4 examples showing NL → JSON extraction:

```
System: You extract graph structure from questions. Output valid JSON.

Example: "Why does the server crash when the database is overloaded?"
{"nodes": [
    {"name": "server", "type": "component"},
    {"name": "database", "type": "component"},
    {"name": "cache", "type": "component"},
    {"name": "overload", "type": "event"}
  ],
  "edges": [
    {"source": "database", "target": "overload", "relation": "causes"},
    {"source": "overload", "target": "cache", "relation": "causes"},
    {"source": "cache", "target": "server", "relation": "causes"}
  ],
  "query_node": "database",
  "target_node": "server",
  "domain": "technology"
}
```

**Phase 5b:** Separate LoRA adapter trained on synthetic (NL question, JSON graph) pairs generated by reversing existing task generators.

**Fallback:** On JSON parse failure, retry once with error feedback. On second failure, keyword extraction produces a minimal 2-node graph.

### TaskRouter

Maps GraphSpec to one of 14 task types using signals from the extracted graph and original query.

**Phase 5a — Heuristic rules:**

| Signal | → Task Type |
|--------|-------------|
| Edge relations include "causes"/"prevents"/"enables" | labeled_reasoning |
| Query asks "how many paths" / "count" | path_counting |
| Query asks "shortest" / "distance" / "how far" | bfs |
| Query asks "is there a cycle" / "loop" | cycle_detection |
| Missing edges / "what connects" | graph_completion |
| Asks about similarity between domains | analogical_transfer |
| Structural question ("how connected", "clustered") | spectral_gap |
| Default fallback | diverse |

Keywords are extracted from the original NL query (preserved alongside GraphSpec).

**Phase 5b:** Small MLP head (14-class) on Llama's pooled hidden state from the parsing pass. Trained on synthetic (query, task_type) pairs. Heuristics kept as fallback.

### CellComplexBuilder

Thin wrapper converting GraphSpec → CellComplex via existing infrastructure.

1. Create `nx.Graph()` from `spec.nodes` and `spec.edges`
2. Store node/edge labels as NX attributes
3. Call `nx_to_cell_complex(G, embedding_dim, source_node, target_node, fill_triangles=True)`
4. Structural embeddings computed automatically (degree, clustering, BFS distance)
5. Edge relation encoding: `emb[1]` = relation type index (causes=0.33, prevents=0.66, enables=1.0)

~30 lines of new code. All heavy lifting in existing `graph_convert.py`.

### AnswerGenerator

Takes model prediction + graph context and generates NL explanation through Llama.

**Phase 5a — Few-shot prompt:**

```
Task type: {task_type}
Original question: {original_query}
Graph: {nodes} with edges {edges}
Query: {query_node} → Target: {target_node}
Prediction: class {class_idx}

Class interpretation:
- bfs: class = hop distance (0-15)
- labeled_reasoning: 0=causal, 1=blocked, 2=independent
- cycle_detection: 0=no cycle, 1=cycle exists
- graph_completion: 0=no edge, 1=edge should exist
...

Generate a 1-3 sentence explanation.
```

**Phase 5b:** Separate LoRA adapter for generation. Trained on synthetic (class_idx, graph_context, expected_explanation) triples.

## NLReasoningPipeline — Orchestrator

```python
class NLReasoningPipeline:
    def __init__(self, checkpoint_path, llama_model, device):
        self.parser = GraphParser(llama_model, device)
        self.router = TaskRouter()
        self.builder = CellComplexBuilder()
        self.model = load_frozen_model(checkpoint_path, device)
        self.answerer = AnswerGenerator(llama_model, device)

    def query(self, text: str) -> NLResult:
        """Full NL → reasoning → NL pipeline."""
```

**Llama sharing:** Parser and AnswerGenerator share the same Llama instance. Each gets its own prompt template. Phase 5b: each gets its own LoRA adapter, swapped via peft's `set_adapter()`.

**Error handling:**
- Parser JSON failure → retry once → fallback keyword extraction
- Router no match → default to diverse
- Model NaN/inf → low-confidence result with warning
- Each stage logs timing for profiling

## Testing Strategy

**Unit tests (~25):**
- GraphParser: valid JSON from 5 sample queries, fallback on malformed output, domain detection
- TaskRouter: correct routing for each heuristic rule, default fallback
- CellComplexBuilder: NX graph from GraphSpec, structural embeddings, node_map, edge relations
- AnswerGenerator: non-empty output per task type, class interpretation
- NLReasoningPipeline: end-to-end with MockLLMBackend, error propagation

**Integration tests (3):**
- Full pipeline mock: NL query → NLResult with all fields
- Frozen model regression: same predictions as unfrozen
- Round-trip: generate labeled_reasoning → extract NL → parse back → compare graph

**Mock-first:** All unit tests use MockLLMBackend. Real Llama tests skip-guarded for GPU.
